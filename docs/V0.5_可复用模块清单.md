# VChat V0.5.1 · TASK-000 可复用模块清单

源码基线 `main` / `11bd5d5`。按可以沿用的能力及其适用边界列出。

| 模块 | 真实入口 | 可复用内容 | Agent 接入边界 |
| --- | --- | --- | --- |
| 账号与会话 | [`authenticateUser()`、`LOGIN`、`JOIN`](../ChatServer/main.cpp#L489)；[`LoginDialog::authenticateWithServer()`](../ChatDemo_1/logindialog.cpp#L1056) | 取服务端已认证 socket 对应的 `qint64` 用户 ID，从房间和任务记录做后续判断。 | 服务端会话保存在内存，Agent 恢复依赖业务库中的任务、成员关系和授权记录。JWT、跨进程会话都不是当前实现。 |
| 房间成员、房主核验 | [`RoomStore::isMember()`](../ChatServer/roomstore.cpp#L74)、[`canManage()`](../ChatServer/roomstore.cpp#L127)、[`create()`](../ChatServer/roomstore.cpp#L325) | 成员资格查询、已解散过滤、数据库中的 `owner_id` 与角色交叉核对。 | `canManage()` 还会允许部分普通成员管理行为，大厅直接拒绝管理。批准动作需要自己的策略。 |
| TCP 帧和分发 | [`sendLine()`](../ChatServer/main.cpp#L145)、[服务端 `readyRead`](../ChatServer/main.cpp#L689)、[`MainWindow::on_socketReadyRead()`](../ChatDemo_1/mainwindow.cpp#L1997)、[`appendIncomingLine()`](../ChatDemo_1/mainwindow.cpp#L3673) | UTF-8 行协议，完整帧分发，Base64 紧凑 JSON 请求/通知，UI 绑定现有 socket 槽。 | 新事件仍需 schema、协议能力协商、收发限额和独立路由；现有前缀只承担各自业务。 |
| 回复关联、错误与去重 | [`AiRoom::streamEvent()`](../ChatServer/airoom.cpp#L247)、[`MainWindow::appendAiStreamEvent()`](../ChatDemo_1/mainwindow.cpp#L3393)、[`handleSummaryShare()`](../ChatDemo_1/mainwindow.cpp#L1613) | 借鉴请求 ID、房间过滤、过期回调丢弃与分享幂等的方式。 | Vivi 请求序号、回复 ID 和分享 ID 各有原语义，均不代替 Agent 持久化事件 ID 或重连补拉游标。 |
| 聊天输入与 Vivi 入口 | [`MentionInput`](../ChatDemo_1/mentioninput.h#L5)、[`MainWindow::setupViviComposer()`](../ChatDemo_1/mainwindow.cpp#L938)、[CHAT2 的提及校验](../ChatServer/main.cpp#L1424) | 复用现有输入控件、Vivi 菜单和服务端校验后的提及对象。 | 任务意图分流需要新增规则；普通 `@Vivi` 仍是对话入口。 |
| DeepSeek 客户端 | [`AiService::complete()` 与 `stream()`](../ChatServer/aiservice.cpp#L103)、[`SseParser`](../ChatServer/aiservice.cpp#L17) | 复用服务端凭据来源、HTTPS、超时、异步回调、SSE 与错误分类。 | 计划和权限由服务端 schema 与白名单校验。模型完成结果是文本，接口现有输出上限为 1024 tokens，须按任务验证。 |
| 对话历史和异步 SQL | [`readAiHistory()`](../ChatServer/main.cpp#L72)、[`roomFor()`](../ChatServer/main.cpp#L619)、[`AiRoom::makeContext()`](../ChatServer/airoom.cpp#L54) | 参考线程内命名连接、结果回到主线程、房间隔离和有限上下文组装。 | `AiRoom` 的上下文与队列为聊天设计。Agent 的任务数据、工作区内容预算和执行重试规则独立。 |
| SQL 事务与幂等 | [`registerUser()`](../ChatServer/main.cpp#L443)、[`RoomStore::create()`](../ChatServer/roomstore.cpp#L325)、[`sendDirectInvites()`](../ChatServer/roomstore.cpp#L478)、[总结分享](../ChatServer/main.cpp#L1166) | 参考参数绑定、行锁、条件更新、事务失败回滚、唯一键和成功写入后发送。 | 当前连接针对业务库，没有通用事务类；需明确 Agent 连接与任务、步骤、授权、事件的事务边界。 |
| 卡片、面板和内容渲染 | [`appendSharedSummary()`](../ChatDemo_1/mainwindow.cpp#L1639)、[`setupViviSummary()`](../ChatDemo_1/mainwindow.cpp#L1239)、[`AiMarkdownWidget`](../ChatDemo_1/aimarkdownwidget.h#L12)、[`SafeMarkdownBrowser`](../ChatDemo_1/aimarkdownwidget.cpp#L33) | 复用 QWidget 布局、消息卡片样式、Markdown 安全渲染思路和加载反馈。 | 计划/执行/结果是结构化状态，宜用独立卡片状态模型；预览和下载须走受授权的接口。 |
| 客户端时间及房间变更 | [`ChatTime::parse()`](../ChatDemo_1/chattimeutils.h#L10)、[`handleRoomNotice()`](../ChatDemo_1/mainwindow.cpp#L2438)、[`clearMessageView()`](../ChatDemo_1/mainwindow.cpp#L2486) | UTC 本地化、房间退出通知、UI 清理和回包按房间隔离。 | 任务进度需支持在正确房间恢复和掉线补拉。时间应使用任务协议的明确格式。 |
| 测试结构 | [Qt 测试目标](../tests/CMakeLists.txt#L6)、[房间协议](../tests/rooms_protocol_test.py)、[总结分享协议](../tests/summary_share_protocol_test.py)、[重启时间测试](../tests/message_time_e2e_test.cpp#L99) | 参考假 SSE、碎帧、双客户端、数据库隔离与进程重启验证。 | 现有测试未覆盖任务审批及文件权限。部分目标会写库或创建临时库，运行前应明确测试实例。 |

后续需要独立设计的能力包括计划 schema 与摘要、审批与状态迁移、受控文件访问、只增产物、持久化进度与重连恢复，以及任务/产物授权查询。上述接口均未在本次盘点中实现。
