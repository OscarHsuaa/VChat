## 2. 盘点发现的风险和处理方向

| 优先级 | 已知现象、影响与后续方向 | 依据 |
| --- | --- | --- |
| P0 | **现有 TCP 未提供传输加密**。Qt 聊天使用 `QTcpSocket/QTcpServer`，`LOGIN` 明文包含密码，`JOIN` 发送可复用令牌。Base64 是结构化帧编码。工作区内容、下载与授权操作上线前需确认部署网络和传输保护。 | [客户端登录](../ChatDemo_1/logindialog.cpp#L1056) · [服务端监听](../ChatServer/main.cpp#L1600) · [DeepSeek TLS 为独立 HTTPS 连接](../ChatServer/aiservice.h#L15) |
| P0 | **数据库凭据与连接边界**。本地业务库连接使用代码内置的高权限账号及凭据。Agent 库建议单独配置权限，连接应在所属线程创建和使用。房间和 Agent 状态若分属独立连接，事务不会自动跨连接；需设计撤权检查和并发顺序。 | [openDatabase](../ChatServer/main.cpp#L153) · [工作线程独立连接](../ChatServer/main.cpp#L72) |
| P0 | **模型输出与工作区文件是低信任输入**。模型返回 `content` 字符串，目前只有协议/回复格式检查；不能据其文字直接决定权限、路径或工具参数。后续须验证计划 schema、白名单、路径边界和文件额度，并在执行时重新检查。 | [模型返回解析](../ChatServer/aiservice.cpp#L126) · [当前聊天低信任提示](../ChatServer/airoom.cpp#L54) |
| P0 | **文件发布的原子性**。任务产物文件与 MySQL 元数据是两类资源。后续要定义“文件已发布但登记未提交”“已审批但计划随后修改”等情况的补偿和恢复策略，预览/下载以服务端当前授权和真实产物匹配为准。 | 当前总结仅用 `chat_history` 记录分享与去重，没有文件系统提交环节。 [分享写库与回包](../ChatServer/main.cpp#L1235) |
| P1 | **主线程负载与帧大小**。当前业务 SQL 多在服务端事件循环同步执行，客户端同一 GUI 线程解析消息和更新控件。`ROOM` 长度校验发生在拿到完整帧之后。Agent 长文本和文件传输需要限定接收/发送队列及消息体大小，重任务移出事件循环。 | [服务端接收缓冲](../ChatServer/main.cpp#L700) · [ROOM 长度检查](../ChatServer/main.cpp#L868) · [客户端接收](../ChatDemo_1/mainwindow.cpp#L1997) |
| P1 | **任务输入不能直接沿用聊天正文约束**。`CHAT2` 接收分支拒绝含换行和超过 4000 个 `QString` 字符单位的消息。需明确多行任务说明、错误显示和任务请求的幂等键。 | [客户端消息构建](../ChatDemo_1/mainwindow.cpp#L1933) · [服务端 `CHAT2` 校验](../ChatServer/main.cpp#L1430) |
| P1 | **迁移草案需按真实数据库校准**。草案的 `VARCHAR(1024)` 产物路径按 `utf8mb4` 最大宽度计算，仅路径就可能占 4096 字节的索引键预算。完整联合唯一索引、大小写行为、重复执行策略和外键删除策略均需在目标 MySQL 验证。MySQL 元数据实查八张表的外键只指向 `rooms`，用户字段没有同类型的外键先例。 | [现有房间迁移](../ChatServer/migrations/003_rooms.sql#L1) · [数据库草案](<D:/Chrome/V0.5_数据库设计.md>) |
| P1 | **现有 AI 时间字段有分支差异**。常规 `AiRoom::streamEvent()` 没有 `created_at`，客户端用空时间兜底，`saveAiHistory()` 也在缺值时用服务端当前时间。其它房间/总结日期仍存在不带时区的序列化。这些路径不能充当 Agent 事件时间契约。 | [流事件字段](../ChatServer/airoom.cpp#L247) · [服务端入库](../ChatServer/main.cpp#L322) · [客户端读取](../ChatDemo_1/mainwindow.cpp#L3408) · [空时间处理](../ChatDemo_1/chattimeutils.h#L10) |
